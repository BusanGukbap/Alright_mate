# Operations threat model

## Scope and trust boundaries

The public boundary ends at the TLS/OAuth gateway. The API, PostgreSQL, Prometheus, exporters and local Garage harness have no host-published ports. The VM operator boundary includes systemd, Docker and restrictive secret files. Production object storage is external and reached over TLS with scoped credentials. The age identity is a separate recovery trust root and is not required for backup creation.

| Threat | Consequence | Preventive control | Detection and response | Residual risk |
| --- | --- | --- | --- | --- |
| Stolen S3 credential | Encrypted backups copied or deleted | Client-side age encryption, scoped bucket credential, object versioning and retention; rclone uses environment-only configuration and creates no credential file | Object audit logs, stale-backup alert, secret rotation | Process-level environment access on the backup host can still expose the scoped credential |
| Compromised backup host | New backups or metrics forged | Public recipient only on host, restricted service account, read-only container and capability drop | System journal, unexpected backup IDs, independent restore drill | Docker access is root-equivalent; harden and audit the dedicated account |
| Leaked age identity | Historical backup confidentiality lost | Identity kept in secret store/offline custody, never in repository or routine host environment | Secret-store audit and scheduled restore access review | A copied identity cannot be revoked for already-encrypted objects; rotate and re-encrypt where required |
| Partial or corrupted upload | False confidence in recovery | Staging prefix, encrypted SHA-256 metadata, `_COMPLETE` marker written last | Backup failure/staleness alerts and restore drills | S3 is not transactional; consumers must enforce marker semantics |
| Restore targets live data | Production loss | Restore script accepts no database target and creates a uniquely named, private, disposable PostgreSQL container | Restore result and Docker container audit | A Docker-privileged operator remains powerful; require change approval and two-person review |
| Public monitoring exposure | Operational and user-count metadata leaked | Internal network, no host port publication and time-limited loopback SSH access to the Prometheus UI/API | Gateway/firewall checks and Compose hardening tests | SSH operators can reach private container addresses during approved sessions |
| Deferred dashboard UI | Rich dashboard visualisation is unavailable | Grafana 13.1.3 is omitted after its official image reported 14 HIGH findings; dashboard and provisioning files are inactive future assets | Compose and inventory contracts prove absence; re-enable only after an official image reports zero unwaived HIGH/CRITICAL findings | Operators use the private Prometheus UI/API and retain API, host-resource and backup signals |
| Deferred container telemetry | Per-container CPU and memory signals are unavailable | cAdvisor and its sole-purpose Docker socket proxy are omitted while GHSA-hrxh-6v49-42gf affects the official release; no monitoring service holds the socket | Compose and inventory contracts prove absence and track the grpc-go >= 1.82.1 upstream threshold | Container-resource metrics are pending, so operators rely on preserved API, node exporter host-resource and backup signals |
| Reduced local retention coverage | A local emulator regression could leave lifecycle behaviour untested | The Garage harness tests encrypted Put, Copy, completion marker, Get, checksum and isolated restore; production retention remains enforced and tested as S3 infrastructure policy | Restore-drill evidence and independent production lifecycle/versioning contracts | Local elapsed-lifecycle API coverage is not claimed |
| Unsafe or opaque backup client | Client vulnerabilities or configuration residue weaken recovery | The distribution-patched rclone package is version-pinned, independently scanned, configured through environment variables with `/dev/null` as its config, and restricted to HTTPS except the private Garage endpoint | Focused image scanning and the real Garage drill verify transport, server-side copy and cleanup | The authenticated backup-tools image must pass its private release scan again for every revision |
| Secret or metrics volume ownership drift | Restore cannot read its identity, or backup metrics become stale | A root-only one-shot initialiser copies the restore identity with exact UID/mode and chowns the shared metrics volume to UID 10001 before dependants start | Rendered Compose contracts plus UID/read/write integration checks | Docker root can inspect named volumes; host compromise defeats container ownership controls |
| OAuth compromise | Unauthorised owner data access | Gateway fail-closed policy, exact callback and owner/domain allow-list | Provider/gateway audit and compromised OAuth runbook | Provider account security remains an external dependency |
| Disk exhaustion | Database or backup failure | Disk pressure alert, persistent volume monitoring and retention policy | Incident runbook and capacity review | Single-VM storage is a shared failure domain |
| Vulnerable image or IaC | Container escape or unsafe deployment | Immutable image digests, Trivy HIGH/CRITICAL gate, expiring exceptions, read-only/no-new-privileges/capability drop | Release scan evidence and incident response | New disclosures after release require rescanning and rotation |

## Non-goals and assumptions

This design does not claim an AWS/Lightsail upload, a production restore, high availability or Kubernetes controls. The Garage profile holds synthetic local data only. Production operators must validate endpoint TLS, bucket lifecycle/versioning, alert routing, restore custody and VM hardening before activation.
