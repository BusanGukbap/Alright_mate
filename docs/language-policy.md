# Language Policy

All project prose—product copy, specifications, ADRs, runbooks, documentation, issue text and comments intended for readers—uses British English. Use forms such as `practise` (verb), `behaviour`, `authorised`, `normalised`, `organisation` and `colour`. Code identifiers, protocol fields, third-party API names and literal standards terms retain their required spelling.

Expression content must be sourced and reviewed by the owner before publication. Every published expression has a valid source URL. The owner verifies that the expression, Korean meaning, tag choice and public note accurately reflect the cited source and are suitable to publish. The product does not generate language content at runtime and does not treat unreviewed draft material as public information.

When comparing British and US English, label the comparison explicitly; quoted source material keeps its original spelling. Automated spelling checks should use an en-GB dictionary and allow unavoidable proper names and technical identifiers through a reviewed project word list.
